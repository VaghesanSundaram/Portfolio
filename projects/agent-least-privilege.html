Agent Least Privilege

A local Python authorization gateway that enforces trusted filesystem policy on the Model Context Protocol (MCP) tool-call path.

RepositoryResume PDF

What it does

An agent connects to alp-mcp-proxy instead of directly to the filesystem server. For each call, the proxy validates a trusted launch-time JSON policy and forwards only requests within the assigned paths, exact arguments, and call quotas.

agent -> alp-mcp-proxy -> MCP filesystem server -> local sandbox

The proxy controls the connected agent's filesystem authority at this MCP boundary. It does not decide whether an allowed action or the model's final answer is correct.

Engineering highlights

  • Strict Pydantic validation produces immutable policy objects before the untrusted MCP session starts.
  • One shared tool contract keeps configuration, authorization, and advertised MCP schemas consistent.
  • Quota reservations are serialized before forwarding to avoid concurrent overuse.
  • Redacted append-only events distinguish denied, completed, timed-out, and unknown outcomes without storing file content.
  • Unit and integration tests exercise the actual client-to-proxy-to-filesystem-server boundary, with strict mypy/Ruff and Windows/Linux CI.

Development history

ALP began as an experiment asking whether external, task-specific authorization could contain unsafe agent tool calls while preserving useful work. I then extracted the enforceable core into this smaller MCP proxy and placed policy checks on the real tool-call path. The proxy and its integration tests are the primary engineering artifact; the earlier experiment is supporting evidence.

What the public release contains

The repository contains the installable proxy package, policy example, pinned filesystem-server fixture, unit and integration tests, and a curated aggregate evaluation record. It does not contain provider traces or the original campaign machinery, so the historical run cannot be independently replayed from this release.

Limits

The evaluation used synthetic local files, one model and effort setting, and one trial per scheduled cell. Its formal nine-family security gate was inconclusive because only seven families were eligible. The result supports containment at the checked filesystem boundary, not production security, model safety, or correctness within allowed files.
