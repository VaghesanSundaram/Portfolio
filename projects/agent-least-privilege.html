Agent Least Privilege

A default-deny Python authorization monitor that binds tool calls to the functions, resources, arguments, approvals, and call limits of the owner task.

RepositoryResume PDF

Question

Can an external monitor limit a tool-using model to the resources, arguments, approvals, and action budget of the owner task? The project evaluates the enforcement layer; it does not claim that a model itself became safer.

Engineering highlights

  • Typed policy and event contracts built with Python 3.12 and Pydantic.
  • Task-scoped checks for functions, resources, arguments, approvals, and call counts.
  • Append-only audit events and deterministic state replay across synthetic services.
  • 93 automated tests, including Hypothesis property checks, with strict mypy and Ruff checks.
  • Continuous integration on Windows and Linux, plus checked-in results and an offline verifier.

Method

I implemented a policy evaluator, synthetic mail, file, ticket, and payment services, append-only audit events, deterministic replay, and evaluation fixtures for resource substitution, argument or destination substitution, approval laundering, call-count misuse, and cross-tool privilege chaining. The same fixtures were evaluated with gpt-5.4-mini under unrestricted execution, a static action allowlist, and task-conditioned enforcement. The 60 completed episodes are a small controlled evaluation, not a population estimate.

Observed result

Observed security outcomes across 10 attack cases and utility across 10 matched controls per condition
ConditionUnauthorized state-changing effectsControl task completion
Unrestricted4 / 108 / 10
Static action allowlist6 / 1010 / 10
Task-conditioned monitor0 / 108 / 10

Under task-conditioned enforcement, the model still proposed unauthorized actions in 5 of 10 attack cases, but the monitor prevented every observed state-changing effect. That distinction is the central result: proposal behavior and enforcement behavior are measured separately.

What the public release contains

The public release includes the authorization core, synthetic services, automated tests, checked-in results, and offline verification. The verifier checks the published artifacts; it does not call a model provider or reproduce the original generation run.

Limits

The evaluation uses synthetic tools, one primary model, ten attack cases, and one trial per cell. It supports a narrow claim about this monitor in these fixtures, not a claim about real-world attack rates, general model safety, or all unauthorized reads.
